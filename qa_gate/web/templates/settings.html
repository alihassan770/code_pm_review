Service credential

Used to read project.task and, later, to write chatter back. It exists because a nightly run has no signed-in person to borrow credentials from, and storing every staff member's password to avoid it would be a far worse trade.

An API key, not a password, Odoo requires one for RPC when the account has two-factor enabled, and it can be revoked without disturbing a password a human also uses. Verified against Odoo before it is stored, and encrypted at rest.

GitHub access

Reads each client's repositories to build the knowledge base, the module list, qa/knowledge.yml and qa/scenarios/. Read-only; this app never pushes to a client repo.

Private repositories need this. GitHub answers an unauthenticated request for a private repo with the same 404 it gives for one that does not exist, so without a token a private repo looks exactly like a typo.

Verified as {{ github_login }}

{% endif %}

Create one at github.com/settings/tokens. A classic token needs the repo scope; a fine-grained token needs Contents: read-only on the repositories, and for an organisation like HSxTech the org must have approved it. Verified against GitHub before it is stored, and encrypted at rest.

AI provider

Used to read addon source and propose what each module does, and to turn a task description into checkable assertions. It never decides whether a review passes, that is computed from assertion results, and a model's opinion is not one. One provider is active for everybody.

Who may change these settings

Two roles. An admin sets the Odoo connection, the service credential and the AI provider, and those apply to everybody. A user runs reviews against them and cannot change them. There is no signup, accounts appear here the first time somebody signs in with their Odoo login.
